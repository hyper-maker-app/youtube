# Zack D. Films 3D Vertical Short Skill

## Canonical output contract

The production path is one persisted, audio-locked `TimelinePlan`: the eight-shot
screenplay is only a pre-TTS outline. After the real voice is probed it locks 6–13
sequential 4.0-second native clips and N+1 Match-Cut keyframes. It persists
`n_blocks`, `footage_duration`, `content_duration`, measured voice duration, and
`target_duration=max(voice+0.4, footage)`. A 1.5-second
`tpad=stop_mode=clone` tail is included inside that final target, never appended as
an additional unplanned freeze. Do not use the obsolete three-block script, fixed
global duration, or a prompt that asks a clip to finish early and hold.

For an economical isolated integration test, `--test-blocks 1` produces one
4.0-second block from two keyframes (plus its 1.5-second tail budget), while
`--test-blocks 2` produces two blocks from three Match-Cut keyframes. Test
timelines are new-run-only and cannot rewrite a resume.

## Causal imagery and asymmetric VFX

Each clip must show one irreversible causal state change: entry state ->
dominant physical event -> exit state -> next question. Keyframes encode an
asymmetric visual transition:

`Keyframe 1 (latent / seed state) -> Keyframe 2 (peak / event state) -> Veo 3.1 physical interpolation`

This is not permission for generic spectacle. Do not inject arrows, neon,
fissures, corona rings, explosions, or phase VFX unless the authored
`proof_on_screen` specifically requires that evidence. Keep the lower-middle
caption-safe zone free; captions are applied by ASS/FFmpeg, never generated by
an image or video model.

## Six-scale lighting matrix

| Scale | Lighting direction |
| --- | --- |
| Wide | Golden daylight, long readable shadows, atmospheric depth, grounded contact shadows |
| Human | Soft key, shallow contrast, natural skin bounce |
| Object | Controlled studio key with a physically motivated edge highlight |
| Macro | Diffuse rim illumination across translucent microstructures |
| Micro | Cool clinical key light with a warm internal practical |
| Nano | Bioluminescent X-Ray Blue through translucent nanoscale structures |

`visual_domain` selects the matching lighting instruction. The subject and
physical proof remain legible above the caption-safe zone.

## Baked proof marker and FFmpeg camera agreement

If proof requires a marker, bake a restrained neon-green directional arrow or
red trajectory into the relevant keyframe/video prompt and name the matching
target quadrant. The editor then pushes into that same quadrant using half-open
windows (`gte(time,t0)*lt(time,t1)`) and dynamically bounded crop coordinates:

`clip(dim * normalized_target - (dim / zoom / 2), 0, dim - (dim / zoom))`

Never change those expressions. A marker is evidence, not a default effect.

## Veo 3.1 Lite RAI prompt preparation

`VertexVeoProvider.sanitize_prompt()` first collapses whitespace, then replaces
case-insensitively:

| Risky wording | Safe visual wording |
| --- | --- |
| `cancer` | `abnormal cellular cluster` |
| `blood` | `crimson fluid` |
| `needle` | `micro probe` |
| `wound`, `cut`, `puncture` | `fissure penetration` |

The sanitized prompt must be no longer than 550 characters and truncates on a
word boundary when possible. Veo prompts still require 9:16, a 4.0-second
native clip, silent video, no captions/logos/watermarks, and closed/neutral
mouths. Prompt sanitization reduces avoidable RAI triggers; it is not a claim
that any provider safety review can be bypassed.

## Canonical compiler and restrained phases

`services.script_engine.compile_keyframe_prompt()` compiles both Match-Cut endpoints,
not just the video motion text. It carries the canonical glossy stylized 3D mannequin /
medical-animation style, 9:16, dark neutral void, warm-gold key and cyan rim lighting,
latent/peak state, caption-safe proof, and neutral-mouth/no-text rules. It rejects
photorealistic/realistic/real-life language. Motion contains diegetic physics only—no
camera push, zoom, dolly, or tracking commands. Each block persists 2–4 coverage beats
for 1.0–1.6-second FFmpeg hard reframes; no cross-dissolve or morphing is permitted.
For human stories, only establish may show an exterior face/body; later shots are
anatomical cutaways, bone/organ/vessel interiors, or microstructure.

## Opening-anchor return payoff

The first shot persists an `opening_anchor_id` backed by its approved roster sheet. It
may identify a human, animal, object, vehicle, structure, organ exterior, or environment.
The final shot may use `return_to_opening_anchor_payoff` only where its explicit
`payoff_reason` proves the final narration beat more clearly. It is never decorative.
This is a separate terminal Veo block after a hard editorial cut: Nano Banana Pro builds
its first frame from the opening-anchor roster (and compatible void/prop sheets) only,
then Veo receives that start frame with no end frame. It must depict one calm diegetic
resolved state, without camera instructions, punch, shake, or a mechanism-to-anchor morph.

## Calm editorial impact and licensed SFX

`editorial_plan` is persisted after narration timing. Every block boundary is a hard cut
with `impact_level: none` unless an authored physical event justifies one isolated
`subtle` 1.2% local reframe. Caption emphasis, a scale change, and subject change never
add punch/shake. Strong emphasis belongs to the source Veo physics rather than an FFmpeg
crash zoom. Effects keep a 0.75-second gap, never stack, and are forbidden into the
terminal payoff and cloned tail.

SFX is optional and must be resolved through a selected licensed provider, never arbitrary
web scraping. Only provenance-complete CC0 or commercially usable CC-BY assets can be
admitted: source and licence URLs, creator, commercial status, local-file SHA-256, tags,
and CC-BY attribution are required. A run writes `sfx_cue_sheet.json`; actual CC-BY usage
writes `ATTRIBUTIONS.txt`. Cues attach only to visible physical events, with no more than
two per block; missing or NC/unknown licensing fails closed.

`establish`, `descend`, `explore`, `reveal`, and `resolve` regulate narrative restraint:
they do not automatically create neon, arrows, trajectories, corona, fissures, or
explosions. A marker is valid only when authored as necessary proof; if present its type
and quadrant must match the target and remain outside lower-middle. No marker is valid.
